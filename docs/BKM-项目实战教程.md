# WorkBuddy 实战教程：如何用 AI 从零做出一个「股票智研」项目

> 目标读者：想学会用 WorkBuddy 的 AI 能力自己造项目的人（本文以本仓库为例，适合作为父子教学材料）。
> 前置：会打开 WorkBuddy 对话窗口，有一台 Linux 电脑，最好懂一点命令行。

这个项目（stock-lens）不是手写出来的，而是**一段对话一段对话"聊"出来的**。下面把完整过程拆成 7 步，每步都给出当时实际用到的提示词（prompt）和背后的思路。学会这套方法，你也能用它造任何网站、工具、脚本。

---

## 第 0 步：先理解 WorkBuddy 的三种工作模式

WorkBuddy 有三种模式，做项目时通常按这个顺序切换：

| 模式 | 干什么 | 什么时候用 |
|------|--------|-----------|
| **Agent（你说，我做）** | 直接动手改文件、跑命令、交付结果 | 想清楚要什么之后，让它一口气做完 |
| **Plan（先想，再做）** | 先给方案，你确认了才动手 | 需求还不清晰、想先看设计 |
| **Ask（只聊，不动手）** | 只回答、只读文件，不改任何东西 | 还在探索、咨询阶段 |

本项目的真实过程：先用 Ask/普通对话把需求聊清楚 → 让 Agent 直接开干 → 遇到问题就让它自己调试。

---

## 第 1 步：把模糊想法说清楚（需求澄清）

**当时的原始需求：**

> "有什么股票分析的 skill 或 agent 吗？我如果给个股票代码，我们可以有个后台 service 去动态分析，分析财务报告、市场数据和产业要闻等等给出卖出买入意见"

**跟着的第二个需求：**

> "要有 Web 页面入口，我可以输入股票代码，给出实时分析和建议"

**关键心法：**
1. 不用一开始就把需求写得多专业，先说出"我想做什么、给什么、得到什么"。
2. AI 会帮你补全行业知识——它发现"股票分析"属于金融场景，就自动加载了金融 skill，告诉你可以做财报、估值、技术面、资金流等维度。
3. 如果你有"参考对象"（比如"像 mistake-book 那样部署到公网"），**直接说出来**，AI 会去照搬那套做法，比从零设计快得多。

---

## 第 2 步：让 AI 自己"找能用的数据源"（最关键的一步）

做这类"要接真实数据"的工具，难点永远不是写页面，而是**数据从哪来**。AI 的做法是：先试、再验、后封装。

**当时让它做的事（用 curl 逐个测接口）：**

```bash
# 测东方财富实时行情
curl -s "https://qt.gtimg.cn/q=sh600519"
curl -s "https://push2.eastmoney.com/api/qt/stock/get?secid=1.600519&fields=f43,f57,f58"
```

**心法：** 你可以直接对 AI 说"帮我去测这几个免费股票接口能不能用，把返回字段搞清楚"，它会自己 `curl`、自己解析、自己总结出"哪个接口稳定、哪个字段是 PE"。这就是 AI 比人强的地方——它能快速试错上百次不嫌烦。

**本项目最后选定的免费数据源（全部是公开接口，不花钱）：**
- 东方财富（主源）：行情、K 线、财报、资金流、龙虎榜、解禁、板块
- 腾讯财经（备源）：主源被限流时自动切换

---

## 第 3 步：让 AI 搭出"能跑的最小版本"（先跑通再说）

不要一上来就要完美功能。正确姿势是：**先做一个能输入代码、能出数字的小页面**，跑通了再慢慢加功能。

**当时的推进节奏：**

1. 先让 AI 用 Node.js 写一个零依赖后端 `server.js`（连 npm install 都不用，最省事）
2. 前端用纯 HTML + CSS + 原生 JS，图表用本地下载的 ECharts
3. 端到端测一只股票（贵州茅台 600519），确认"数据 → 指标 → 页面"全通

**心法：** 告诉 AI"先做一个最小可用版本，别的以后再加"。你会看到它自己建了任务清单（TaskCreate），一步步标记完成——这是它在自我管理进度。

---

## 第 4 步：遇到坑，让 AI 自己排查（不要替它下结论）

开发中一定会遇到"接口突然抽风""美股 K 线间歇失败"这类问题。**正确做法是：把现象告诉 AI，让它自己加日志、自己定位、自己修**，而不是你手把手教。

**本项目踩过、并最终沉淀成经验的坑（现在已写进项目注释）：**

| 坑 | 原因 | 解法 |
|----|------|------|
| 东财接口间歇断连（`UND_ERR_SOCKET`） | 出口 IP 被 TLS 指纹级限流 | 三层请求链路：undici fetch → 经典 https → curl 兜底 |
| 用 Node 拉不到数据但 curl 能通 | 两者 TLS 栈不同 | 同上，互相备份 |
| 美股 K 线只有 2 条 | 腾讯美股代码要带交易所后缀 `.OQ`，拼成 `usAAPL.OQ.OQ` 就废了 | 归一化代码，别重复加后缀 |
| 财报字段名写错 | 凭记忆写字段名 | 先用 `columns=ALL` 拉一行看真实字段名 |

**心法：** 对 AI 说"还是不行，帮我加日志看看到底哪一步挂了"，它会自己去复现、打印、定位。你只需要描述"现象 + 期望"，不用懂底层。

---

## 第 5 步：加入 AI 大模型，但要"分层"（本项目精华）

规则引擎（纯数学公式）能算指标、打分，但读不懂新闻含义。于是引入 DeepSeek 和 Kimi 两个大模型。**关键设计：让它们各司其职、只解读真实数据。**

**当时的核心提示词设计（这是可以复用的模板）：**

给两个模型的系统提示里都有一条"铁律"：

> 铁律：只能解读我提供的数据，严禁编造数据中没有的数字、事件、研报观点或日期。引用数字必须来自数据包原文。

然后：

- **Kimi（长文本强项）** → 通读新闻公告，逐条判断利好/利空/影响
- **DeepSeek（推理强项）** → 拿到完整数据包 + 规则引擎结论，写综合研报

**心法：** 别让 AI"全包"（那样它会编数字），而是"AI 负责解读语言，公式负责算数字"，两者边界清晰。这是本项目最重要的工程思想。

---

## 第 6 步：发布到公网 + 加访问口令

**当时的真实需求：**

> "可以做成外网方式网页吗？就像我们本机部署的 mistake-book 一样，用的 webservice: https://cuoti.vip.cpolar.cn"

AI 的做法是：**先去翻 mistake-book 的部署配置**，照同样的 `cpolar` 隧道模式，把本项目用一个新子域名 `stocklens` 暴露出去。

加口令也很简单，一句需求搞定：

> "请增加个令牌密码第一次时候需要输入，后面可以放到浏览器本地缓存，令牌密码设为: <请设置新的访问口令>"

**心法：** "照 XX 项目那样做" 是最高效的提示词——AI 会去读那个项目的配置、复制模式，省掉你重新描述。

---

## 第 7 步：沉淀成文档（你现在看的这份）

最后让 AI 把整个过程整理成 README / DESIGN / DEPLOYMENT / 教程文档，方便复习和交接。

**你可以这样问：**

> "帮我写一份教程，教一个初学者如何用 WorkBuddy 的 AI 生成类似项目，以这个股票项目为例，包含用到的提示词和后台技术。"

## 一张图记住整个项目

```
用户输入代码
   │
   ▼
[数据层] 东财主源 + 腾讯备源（免费公开接口，三层容错）
   │
   ▼
[规则引擎] 7 维评分 + 多空辩论 + 条件化买卖参考（纯公式，秒出）
   │
   ├──► 页面直接展示（行情/K线/资金流/财报/A股特色）
   │
   └──► [AI 研报] Kimi 读消息面 ∥ DeepSeek 写研报（约 1~3 分钟）
```

## 技术栈清单（面试/复习可用）

- **后端**：Node.js（零 npm 依赖，`http` + `https` + `child_process` 原生模块）
- **前端**：原生 HTML / CSS / JS + ECharts 5（本地 vendor）
- **数据源**：东方财富、腾讯财经免费公开接口
- **AI**：DeepSeek V4-Pro、Kimi k2.6（OpenAI 兼容 `chat/completions`）
- **部署**：cpolar 公网隧道 + systemd 服务

## 给你的练习建议

1. 把 `server.js` 里 `analyzeAll()` 的评分规则读一遍，试着改一个阈值，看评分怎么变
2. 把 `llm.js` 里给模型的提示词改成"偏保守"，观察 AI 研报语气变化
3. 照这套方法，自己做一个"天气查询"或"汇率换算"小工具练手

---

> 一句话总结：**会提问 + 让 AI 自己试错 + 分层设计 + 沉淀文档**，就是 WorkBuddy 造项目的全部诀窍。
